## עקרון התוכן: משכנעים קודם, מבקשים אחר כך

עמוד הבית לא מבקש פרטים לפני שקראו אותו. סדר הקריאה נמדד: תחומי העיסוק בצומת 19, דרך העבודה ב-79, **הבקשה הראשונה ליצירת קשר ב-161 מתוך 166** — כלומר רק בסקשן הסוגר.

מה שהוסר בכוונה ולא יחזור:

- טופס לידים בהירו
- כפתורי וואטסאפ/חיוג צפים
- בר פעולות תחתון במובייל
- רצועת מספרים ראוותנית

`gates/verify-restraint.mjs` אוכף את זה על הפלט הבנוי: 11 כללי איסור, ולכל היותר **2 כפתורי CTA לעמוד**. יש לו בקרה שלילית (`verify-restraint-control.mjs`) שמוודאת שהבודק באמת נכשל כשמחזירים דפוס אסור — בודק שרק אומר "עבר" חסר ערך.

## כתובת — פורסמה לבקשת הלקוח (2026-08-25)

הכתובת **רח׳ האר״י הקדוש 20, פתח תקווה** מופיעה בפוטר, בעמוד יצירת הקשר, בהצהרת הנגישות וכ-`streetAddress` ב-JSON-LD.

זה **היפוך של החלטה קודמת**. קודם לכן לא הופיעה באתר שום כתובת, בנימוק שאין משרד שמקבל קהל ושהכתובת שבקורות החיים היא ככל הנראה פרטית. ליאור אישר את הפרסום במפורש אחרי שהנימוק הוצג לו שוב.

**מה עדיין לא נוסף, ובכוונה:**

- `openingHoursSpecification` — שעות פעילות מעולם לא הגיעו מהלקוח. השעות שהופיעו פעם (א׳–ה׳ 09:00–18:00) היו הנחה שלי והוסרו. אין להמציא אותן מחדש.
- `geo` ומפה — לא אומתו קואורדינטות.
- ניסוח ״בתיאום מראש״ — ליאור פסל אותו במפורש.

**שאלה פתוחה שמשפיעה על חובות חוקיות:** האם הכתובת הזו מקבלת קהל בפועל? אם כן, חוק שוויון זכויות לאנשים עם מוגבלות מחייב סעיף נגישות מבנה בהצהרת הנגישות. הסעיף שם כרגע נושא סימון `[ להשלמה על ידי הלקוח ]` על פרטי הגישה, החניה, המעלית והשירותים — אלה לא הומצאו, וצריך למלא אותם או להצהיר שהמקום אינו מקבל קהל.

## SEO

12 עמודים אינדקסביליים, עמוד ייעודי לכל תחום עיסוק עם מילת מפתח משלו. title ותיאור ייחודיים, canonical, Open Graph, `sitemap.xml`, `robots.txt`, פירורי לחם, קישוריות פנימית.

**Schema.org:** `Attorney` בכל עמוד (שם, טלפון, עיר ומחוז, אזורי שירות, קטלוג שירותים — כולל כתובת רחוב, בלי שעות פעילות ובלי geo), ובנוסף `Service` + `FAQPage` + `BreadcrumbList` בעמודי התחומים, `Person` באודות, `ContactPage`, `ItemList`, `WebSite`.

**ביצועים:** CSS אחד ו-JS אחד (defer), פונטים עם `preconnect` ו-`display=swap`, נכסים עם hash תוכן לקאשינג ארוך, `width`/`height` על תמונות למניעת CLS.

## אימות

`GATES.md` הוא חוזה השלמה מכונתי (סקיל `unlazy`). עשרה שערים: שבעה רצים, שלושה ידניים עם ראיות מתועדות.

```bash
node ../.agents/skills/unlazy/scripts/gate-lint.mjs GATES.md
node ../.agents/skills/unlazy/scripts/gate-check.mjs --status GATES.md
```

להרצה בפועל צריך אישור מפורש של הפקודות. **על Windows** יש באג בסקיל: `lstat().dev` מחזיר 0 בעוד `fstat().dev` מחזיר את הסריאל האמיתי, ולכן בדיקת החבלה על רשומות האישור נכשלת בכל קריאה חוזרת. העקיפה:

```bash
rm -f ~/.unlazy/approved/*.json
node ../.agents/skills/unlazy/scripts/gate-check.mjs --approve --reverify GATES.md
```

## פריסה

`dist/` סטטי לגמרי. Netlify, Cloudflare Pages, Vercel, GitHub Pages או אחסון רגיל.

### שימור תוכן מ-Manager Site

סביבת הלקוח בפרודקשן היא `/client/pinhas_ratzon`. קובץ ההרשאות `/root/Manager_Site/data/clients/pinhas_ratzon/client.config.json` מגדיר תמונות JPG ושדות טקסט מסומנים ב-`data-manager-text` שאפשר לעדכן דרך הממשק.

לפני החלפת תיקיית האתר, `apply-manager-content.mjs` מעתיק אל הבנייה החדשה את התמונות המנוהלות מהאתר החי, את ערכי הטקסט הנוכחיים ואת גרסאות ה-cache busting של קישורי התמונות. לאחר מכן `check-manager-content.mjs` מאמת שכל התמונות קיימות ומקושרות ושכל סימון טקסט מופיע פעם אחת בדיוק. אסור להסיר את שני השלבים האלה, אחרת פריסת Git רגילה עלולה למחוק עריכות שביצע הלקוח.

הדומיין מאפשר הטמעה ב-iframe רק מעצמו ומ-`https://vee-app.co.il`, לצורך התצוגה המוגנת של Manager Site במחשב ובטלפון.

`public/_headers` מוגדר ל-Netlify/Cloudflare Pages. בשרת Apache/Nginx להעביר את אותם כללים ל-`.htaccess` או לקונפיג.

**הטופס** מוגדר ל-Netlify Forms. באחסון אחר להחליף את `FORM_ACTION` ב-`src/site.mjs` ולחבר Formspree, EmailJS או סקריפט שרת. יש שדה honeypot נגד ספאם.
